# BaroSit 채널 마케팅 실행 Skill

비용 0 채널(크리에이터 아웃리치·Q&A 시딩)을 실제로 굴리는 절차. 전략과 템플릿은 이 파일에 없다.

## 원칙: 문서 역할 분담 (중복 금지)

- **`docs/마케팅전략.html` §10~12 = 전략·링크 규칙·메일 템플릿·답변 템플릿·추적표의 단일 진실.** 이 skill 에 복사하지 않는다.
- **이 SKILL.md = 절차의 단일 진실** — 단계·게이트·함정·검증 방법.
- 메모리(`barosit-seo-marketing`)는 세션 간 포인터일 뿐. 충돌하면 마케팅전략.html 과 이 파일이 우선.
- **추적표(§12 `#outreach-tracker`)가 진행 상태의 단일 진실.** 세션이 바뀌면 여기부터 읽는다.

## 절대 규칙

1. **Claude 는 메일을 보내지 않고 커뮤니티에 글을 올리지 않는다.** 초안까지 만들고, 발송·게시는 사용자가 직접 한다. 다음 세션이 이 줄을 무시하고 진행하지 말 것.
2. **리포지터리는 공개다.** 크리에이터 이메일 주소·개인 연락처를 추적표나 커밋되는 어떤 파일에도 적지 않는다. 구독자 수는 구간으로.
3. **슬러그는 로마자만**(`a-z 0-9 _ -`). 한글은 `parseGoPath` 에서 **에러 없이 조용히 무시**되어 추적이 통째로 날아간다. 바른자세tv → `barunjase_tv`.
4. 리서치 결과·발송 사실은 **그 자리에서 추적표에 반영**한다. 대화창에만 남기면 다음 세션이 처음부터 다시 찾는다.

## 모드 파싱

인자에서 `research` / `seed` / `review` 가 있으면 해당 모드, 없으면 **아웃리치 모드(기본)**.

## 0. 로드 (모든 모드 공통)

1. `docs/마케팅전략.html` §10~12 를 읽는다 — §10 링크 규칙·측정 한계, §11 Q&A 3원칙·템플릿, §12 타깃 기준·메일 템플릿·추적표.
2. 추적표에서 현재 상태를 파악한다(누가 후보·발송·팔로업 대기인지).

## 아웃리치 모드 (기본)

### 1. 대상 선정 → [게이트 A: 사용자 확정]

- 추적표에서 다음 대상을 고른다. 우선순위: `팔로업` 기한 도래 > `후보` 중 기준 적합도 높은 것.
- **팔로업 기한(1차 발송 +7일)이 지난 건이 있으면 신규 발송보다 먼저 처리한다.** 팔로업은 1회뿐이고 시점을 놓치면 그냥 무응답 처리다.
- 후보가 없으면 리서치 모드를 먼저 돌리자고 제안하고 중단.

### 2. 슬러그·링크 생성

- 슬러그 규칙: 로마자 소문자+언더스코어, 10자 내외. 채널명이 길면 앞부분만. 영문 채널명은 그대로 소문자화.
- 링크 두 개를 만든다(§10 규칙):
  - `https://barosit.com/go/creator/<슬러그>_outreach` — 1차 메일용
  - `https://barosit.com/go/creator/<슬러그>_video` — **아직 주지 않는다**
- 슬러그가 추적표에 이미 있으면 재사용(같은 채널에 값이 두 개 생기면 성과가 쪼개진다).

### 3. 메일 초안 → [게이트 B: 사용자 검토·발송]

- §12 템플릿(ko/en/ja)의 **구조만** 재사용하고 문장은 채널마다 새로 쓴다. 복붙은 대량 발송으로 읽혀 답장률이 무너진다.
- **`[구체적인 영상 한 편 언급]`을 반드시 채운다.** 이 한 문장이 진짜 메일과 스팸을 가른다. 채널을 실제로 보지 않았으면 여기서 멈추고 사용자에게 확인한다 — **보지 않은 영상을 지어내지 말 것.**
- 링크는 `_outreach` 하나만. `_video` 를 1차에 넣으면 "언급 안 하셔도 됩니다"와 모순되어 협찬 제안이 된다.
- 초안을 제시하고 **사용자가 직접 발송**한다. 발송 여부를 사용자에게 확인받는다.

### 4. 추적표 갱신

- 상태 `발송`, 1차 날짜, 팔로업 예정일(+7일)을 기록하고 커밋 여부를 사용자에게 확인.

### 5. 응답 처리 (다음 세션에서 이어짐)

- **응답 있음** → ① 상태 `응답` ② 평생 무료 발급 안내: **어드민 › 가입자 관리에서 사용자가 직접** "평생 무료 지정"(Claude 는 로그인하지 않는다). 계정은 크리에이터마다 개별 발급 — 공유 계정 금지(자세 데이터가 섞여 "내가 나아졌다"는 서사가 사라진다) ③ 영상 얘기가 나오면 `_video` 링크를 **별도 메일**로 보내며 **"이전 메일의 주소 대신 이걸로"** 를 반드시 덧붙인다.
- **무응답** → 팔로업 1회(+7일). 그 이후는 스팸이다. 상태 `무응답` 으로 닫는다.
- **답장이 와도 영상을 먼저 요구하지 않는다.** 감상만 묻는다 — 먼저 제안하게 만드는 것이 목적이다.

## 리서치 모드 (`research`)

### 1. 기준 확인

§12 타깃 기준을 그대로 쓴다(구독 5천~5만 / 재택·데스크셋업·물리치료·거북목·생산성·개발자 브이로그 / 최근 3개월 활발 / 비즈니스 문의 공개). 이미 다른 자세 앱 협찬을 한 채널은 배제가 아니라 **가점**(주제 적합성이 검증됨).

### 2. 탐색 → [게이트: 후보 목록 제시]

- 웹 검색으로 후보를 찾되 **구독자 수·최근 업로드·이메일 공개 여부는 채널 페이지에서 직접 확인**한다. 검색 요약만 보고 적지 말 것.
- 확인 불가한 항목은 비워두고 "미확인"으로 표시한다. **추정치를 사실처럼 적지 말 것.**
- 후보와 근거(왜 적합한지 한 줄)를 제시하고 사용자 확정을 받는다.

### 3. 추적표 반영

- 확정된 후보를 상태 `후보` 로 추가한다. **이메일 주소는 넣지 않는다**(공개 리포). 구독자는 구간으로.

## 시딩 모드 (`seed`)

### 1. 질문 탐색 → [게이트: 대상 확정]

- §11 타깃 면(지식iN·r/posture·r/ergonomics·개발 커뮤니티)에서 **이미 질문이 올라온 곳**을 찾는다. 수동적 청중에게 밀어넣는 글은 이 스킬의 범위가 아니다(§11 기각 근거 참조).
- 각 면의 자기홍보 규칙을 **답변 작성 전에** 확인한다.

### 2. 답변 초안 → [게이트: 사용자 검토·게시]

- §11 3원칙 준수: ①제품 없이도 도움이 되는 답이 8할 ②만든 사람임을 먼저 밝힘 ③문장은 매번 새로.
- 근거 문장은 `docs/posture-evidence-and-reflection.md` 인용 규칙을 따른다. **PRI·27kg 수치 인용 금지.**
- 링크는 §10 규칙으로 `barosit.com/go/<면>/<주제슬러그>`. 게시는 사용자가 한다.

### 3. 기록

- 어느 면에 어떤 슬러그로 답했는지 추적표 아래 또는 §11 체크리스트에 남긴다. **주 3건 리듬** — 하루에 몰아 쓰면 패턴이 잡혀 스팸 처리된다.

## 리뷰 모드 (`review`)

### 1. 데이터 확인

- **어드민 › 사용 분석 › 유입 채널**(RPC `admin_usage_channels`, 기간 7/30/90/전체·검색·`ref:` 숨김)에서 슬러그로 조회한다. Claude 는 어드민에 로그인하지 않으므로 **사용자에게 화면 값을 받아** 판단한다.
- 프로덕션 SQL 직접 조회는 막혀 있다. 필요하면 §10 의 SQL 을 사용자가 SQL Editor 에서 돌린다.

### 2. 판단 기준

- **`activated`(캘리브레이션 성공 = 실제로 써 봄) 로 판단한다.** 랜딩·CTA 만 많고 활성화 0인 채널은 잘못된 청중.
- **랜딩·CTA = 건수 / 앱 진입·활성화 = 고유 설치 수** — 단위가 달라 서로 나누면 안 된다.
- 앱 진입은 많은데 활성화가 급락하면 **채널 문제가 아니라 제품 문제**(카메라 권한·캘리브레이션 실패). 채널을 접지 말고 제품을 본다.
- 영상 공개일에는 **`직접/미상` 행도 함께 본다** — 상당수는 링크 대신 검색으로 들어와 캠페인에 안 잡힌다. `_video` 숫자는 항상 과소집계다.
- 절대 유입수가 아니라 **채널 간 상대 비교**로만 읽는다(localStorage 기반이라 시크릿·기기 변경 시 유실).

### 3. 결정 → 추적표·문서 반영

- 활성화가 나온 채널에 시간을 더 쓰고, 2주간 0인 면은 접는다. 결정과 근거를 §12 또는 §11 에 한 줄로 남긴다.

## 함정 (겪은 것만)

- **"검색해도 내 답변이 안 보인다"는 정상이다.** 지식iN 검색이 찾는 단위는 **질문**이고 답변은 거기 딸려 간다. 새로 단 답변은 검색 결과로 뜨지 않는다. 게시 여부를 의심하지 말고 **로그아웃 상태로 질문 URL 을 직접 열어** 확인할 것 — 이걸 안 하고 링크 필터·계정 등급 같은 가설만 늘리다 시간을 버렸다(2026-07-29). **가설을 세우기 전에 10초짜리 확인부터.**
- **지식iN 답변의 외부 링크는 걸리지 않는다**(2026-07-29 확인). OG 카드로 렌더링되며 비로그인 노출도 정상. 카드에는 호스트만 표시되므로 `/go/` 경로가 먹히는지는 **유입 채널에 행이 생기는지**로 확인한다.
- **브랜드명 검색 안내(`"바로씻" 네이버 검색`)로 링크를 대체하지 말 것.** 유입 측정이 통째로 사라져 채널 존폐 판단 근거가 없어지고, `바로씻` 은 형태소가 `바로`+`씻다` 로 쪼개져 노출도 불확실하며, `검색!` 문장이 링크보다 더 광고처럼 읽힌다.
- **질문 선별은 답변 수가 아니라 조회수·날짜로.** "의사 답변이 이미 달렸으니 낄 자리가 아니다"로 배제했던 질문(답변 9개·조회 337·최근)이 실제로는 가장 나은 자리였고, 답변 0개인 5개월 전 질문은 아무도 보지 않는다. **검색 옵션을 최신순+1주/1개월로 좁혀 고를 것.**
- **시딩 모드의 "질문 탐색"은 Claude 가 못 한다.** 네이버(`kin.naver.com`·`search.naver.com`·`naver.com`)와 Reddit 은 **인앱 브라우저·사용자 Chrome·웹검색 전부에서 도메인 차단**이다(2026-07-29 확인). 우회하지 말 것. **분업**: 질문 탐색·게시는 사용자가, 답변 초안은 Claude 가. 사용자가 질문 URL·본문을 붙여넣어 주면 그때부터 §11 절차대로 진행한다. 질문 원문 없이 초안을 쓰면 3원칙 ①(질문에 대한 진짜 답이 8할)을 지킬 수 없다.
- **검색 요약의 채널 정보는 절반이 틀렸다.** 2차 리서치에서 "물리치료사 10년차 비니"는 실제로 **구독 35명·영상 0개**인 동명 채널이었다(1차의 `@geobukmok` 도 같은 사례). **반드시 채널 페이지를 직접 연다.**
- **구독자 수는 도달을 보장하지 않는다.** 상한을 폐지한 뒤에 특히 그렇다 — 52.8만 채널의 최근 영상이 897회인 반면 17.8만 채널은 3.3만회였다. 후보 판정 때 **최근 영상 조회수를 함께 볼 것**.
- **한글 슬러그는 조용히 실패한다.** 랜딩은 정상으로 뜨고 추적만 안 돼서, 나중에 "반응 없는 채널"로 오해한다.
- **긴 utm 주소는 크리에이터가 안 붙인다.** 잘라내거나 자기 단축링크로 바꿔 캠페인이 소실된다. 그래서 `/go/` 를 쓴다.
- **`_outreach` 와 `_video` 를 동시에 주면 섞인다.** 다만 섞여도 알아볼 수는 있다 — `_outreach` 가 3 → 200으로 튀면 그건 시청자 트래픽.
- **평생 무료는 베타 중에 검증되지 않는다.** `staged` 모드에서 비테스터는 전원 PRO 로 보이므로, 지정이 실제로 먹히는지 보려면 그 계정을 **테스터로 먼저 지정**해야 한다(지정 전 FREE 로 보이는 것까지 확인해야 의미가 있다).
- **마이그레이션은 사용자가 대시보드 SQL Editor 에 직접 붙여넣는다.** MCP `apply_migration` 은 권한 거부, CLI 는 DB 비밀번호 프롬프트에서 멈춘다. `supabase db push` 는 미커밋 시드 마이그레이션까지 올려버리니 쓰지 말 것.
